tabelline in a Lustre app

The research post tabelline in the browser, from Gleam ended with a plan of five steps. This is the plan, built: tabelline passes its tests under nim js, a build can leave out the icons and the datasets, Gleam's binding runs on both its targets with the same HTML, a table is a Lustre element, and a demo with two tables that build again at every change. What was built, the three bugs the tests found, what it weighs, and how it is built.

Try it

The demo is one HTML file, with its Gleam code explained under it. Two tables, built again by tabelline, in the page, at every change:

  • the planets, the table every port of tabelline draws: change its title, its locale, the decimals of the mass, the palette of the moons and the line above which they are bold, and draw it as HTML, text or Markdown;
  • a dataset: pick one of the eight that come with tabelline (gtcars, countrypops, isole...) and how many of its first and last rows to show, as gt's gt_preview() does.

What the tests found

The research post fixed two things and drew one table, the planets, with the same HTML as Nim. Running all of tabelline's tests under nim js found three more: every test passed in C, and three of them failed in Node.

Five things
that broke under nim js, and their fixes
what brokewhy, and the fix
a file name for an imagea browser has no files: fileExists and readFile do not compile. Fix: under JavaScript a file name raises a ValueError; an address works (research post).
a big const stringnim js writes it out again at every use: the locales' lookup hung, and the icons made 18 MB. Fix: bound once with let (research post).
formatNumber(2.25, 1) was 2.3JavaScript's toFixed rounds a tie up; C's printf rounds it to the even digit, 2.2. Fix: fixed(x, decimals) finds a tie from the number's exact digits, and rounds it to even.
colsAlignDecimal padded nothingit changed each cell through a ptr string, and under JavaScript the change was lost. Fix: an iterator that yields each cell as a var string.
two tests that write a fileno files under JavaScript. Fix: a branch when defined(js) that checks what JavaScript can do instead.

The tie is the one that matters most: tabelline's promise is the same output on every backend, byte for byte, and 2.25 to one decimal is the kind of number a table shows. The fix, in formats.nim:

func fixed*(x: float, decimals: int): string =
  when defined(js):
    result = $toFixedJs(x, decimals)
    let exact = $toFixedJs(x, decimals + 30)   # the double's exact digits
    let cut = exact.len - 30
    if exact[cut] != '5' or exact[cut + 1 .. ^1].anyIt(it != '0'): return   # not a tie
    # a tie after an even digit: keep the digit (toFixed rounded it up)
    ...
  else:
    formatFloat(x, ffDecimal, decimals)

A double is a binary fraction, so it has a finite decimal expansion, and toFixed writes it exactly when asked for enough digits: 2.25 is 2.250000..., a tie; 2.35 is 2.350000000000000088..., not one, and rounds up on both backends.

Gleam, on both targets

The Gleam package is the typed API of the polyglot repository: a table of your own records, columns read from them, formats, styles and errors as Gleam types. It had one function written in Erlang that the JavaScript target needed: render, and the three that write JSON numbers and strings. Each now has a JavaScript twin beside it:

@external(erlang, "tabelline_ffi", "render")
@external(javascript, "./tabelline_ffi.mjs", "render")
fn render_spec(spec: String, format: String) -> Result(String, String)

On the JavaScript side a Gleam Float is a JavaScript number, and JSON.stringify(2.0) is 2: tabelline would read an integer. json_float writes a whole float with its .0, as Erlang does, and a test says so. Then the same planets.gleam prints the same HTML on both targets, and tools/polyglot.nim checks it as a fourteenth port, gleam-js.

The demo needed two things the API did not have: a table from a dataset, and a preview.

tabelline.from_dataset(Gtcars)
|> tabelline.preview(top: 5, bottom: 1)
|> tabelline.to_html

from_dataset gives a Table(Nil): its columns are the dataset's. In the spec it is {"dataset": "gtcars"}, and the spec reads all eight datasets now, each once: countrypops takes 200 ms to parse in JavaScript, too long to wait at every change of a slider.

A table is a Lustre element

tabelline_lustre is a package of its own, so that tabelline keeps no dependencies. It has four functions:

pub fn view(table: Table(row)) -> Element(msg) {
  view_with(table, [])
}

pub fn view_with(table: Table(row), attributes: List(Attribute(msg))) -> Element(msg) {
  case tabelline.to_html(table) {
    Ok(drawn) ->
      element.unsafe_raw_html("", "div", [attribute.class("tabelline"), ..attributes], drawn)
    Error(error) -> problem(error)
  }
}

and view_text, view_markdown, which put the table in a pre. A table that cannot be drawn is a paragraph that says why. An app never sees unsafe_raw_html: tabelline escapes every value it writes, so its HTML can go in the page as it is.

The demo's view is then two calls, one for each table, and the model is the controls: a title, a locale, a number of decimals, a Palette, a number of moons, an Output, a Dataset and two numbers of rows. Every choice is a Gleam type, so a drop-down is a list of typed values and their names.

fn view(model: Model) -> Element(Msg) {
  html.main([class("page")], [
    section("The planets", planet_controls(model), draw(planets_table(model), model)),
    section("A dataset", dataset_controls(model), draw(dataset_table(model), model)),
  ])
}

(Simplified: the demo also times each table.)

How it is built

nim r lustre/demo/build.nim, in tabelline-polyglot, does four things:

  1. nim r js/build.nim --datasets compiles js/tabelline_js.nim with nim js -d:release -d:tabellineIcons=false -d:tabellineDatasets=true, and writes it as an ES module into the Gleam package, gleam/src/tabelline_nim.mjs (not committed).
  2. gleam build in lustre/demo/ compiles the app, tabelline, tabelline_lustre, Lustre and Gleam's standard library to JavaScript modules.
  3. esbuild follows the imports from entry.mjs and writes one minified script.
  4. The script goes in page.html, which holds the style: one file, dist/index.html.

CI runs the same build (.github/workflows/demo.yml), tests the Gleam package in Node first (gleam test --target javascript), and on main publishes the page on GitHub Pages. In tabelline, CI runs the tests under JavaScript and the lean build at every push, so the JavaScript backend stays working.

What is next

Lustre's server components, with the NIF on the BEAM: the same tabelline_lustre.view, drawn on a server. And the Gleam package on Hex, with the JavaScript build of tabelline inside it, so gleam add tabelline is all a user does, on either target.
