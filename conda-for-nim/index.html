So, what about Nim?

Conda, THE package manager for Nim?

Nim has had three package managers in twelve years, and all three read the same file: a list of about three thousand names and git URLs. Conda comes from the other side: it started as "the Python package manager that is not pip", and is now a general, language-agnostic way to ship files into a folder, with compilers, C libraries, Rust, R and CUDA in the same environment. This page explains both, shows the one idea that makes them different, and then does it: nimib and its dependencies built as conda packages, installed with pixi, building a nimib page, with no nimble anywhere.

The short version
  • Nim today: nimble, atlas, nimby and the newcomer clue all start from packages.json, which knows a package's name and git URL, and nothing else. Versions are git tags, dependencies are in .nimble files, so every tool must clone to find out what to clone next.
  • Conda today is not Anaconda's Python installer any more: conda-forge has about 35,000 packages, pixi is a fast, project-first tool from prefix.dev (Wolf Vollprecht, who started mamba), rattler-build builds packages from a YAML recipe. Packages carry their metadata, so the whole dependency graph is known before downloading anything.
  • It already half works: pixi add nim gives you Nim 2.2.6 with its own gcc on Linux and Intel Macs. The missing bridge is one environment variable: Nim already honours NIMBLE_DIR.
  • The PoC: nimforge (under 200 lines of Nim) turns a packages.json entry into a recipe; 13 Nim libraries (and the bridge) built, tested and installed this way, plus treeform's nimby itself as a conda package, and Nim 2.4.2 rebuilt with the bridge built in.
  • Nim is already in conda: one compiler feedstock on conda-forge (stuck at 2.2.6, no Apple Silicon) and about twenty genomics tools on bioconda, by Brent Pedersen, Andrea Telatin, PacBio and others. Nobody ships Nim libraries yet.
  • Others went first: R (3,844 packages on conda-forge), Zig's compiler, Mojo's and Common Lisp's community channels on prefix.dev, RoboStack's ROS packages generated from ROS's own registry. Nim can copy the best of each.
  • Smallest next step: become a maintainer of nim-feedstock, merge the waiting 2.4 update, add osx-arm64 and the NIMBLE_DIR activation. Everything else builds on that.

Nim's package managers, and the phone book they share ↑ Contents

Every Nim package manager starts from nim-lang/packages: one file, packages.json, edited by pull request. This is the whole entry for nimib:

That is all the registry knows: a name, a git URL, a license, some tags. No versions, no dependencies, no checksums, no files. Versions are git tags in nimib's repository, and its dependencies are in nimib.nimble, a NimScript file at each tag. Of the 2978 packages, 2847 live on GitHub, the rest on sourcehut, GitLab, Codeberg and friends. Four tools read this file, each with its own idea of what to do next:

nimble

dom96 (2014), now nim-lang; 0.28 in Nim's koch
the official one

Downloads into ~/.nimble/pkgs2/name-version-checksum. Reads .nimble files (now with a declarative parser, without running NimScript), solves versions (SAT solver since 0.16, PubGrub the default since 0.28), lock files, nimble develop.

atlas

Araq (2021, own repo since 2023), ships with Nim 2.0
a workspace, not a store

Clones dependencies into the project's deps/ and writes their paths into nim.cfg, so the compiler needs no package manager at all. SAT solver, lazy loading, parallel clones, --autoenv to install the right Nim.

nimby

treeform (since 2019), now 0.2.4
just git, at HEAD, in parallel

Shallow-clones every dependency at HEAD into one visible workspace, in parallel, and writes nim.cfg. No resolution on purpose. A lock file (name, url, commit) for CI. Also installs Nim. Fidget2's CI went from 2 minutes to 3 seconds.

clue

George Lemon, OpenPeeps (April 2026), now 0.3.9
a store, a DFS, and the rest of the toolbox

Installs into one store, ~/.clue/packages, and passes --path to the compiler (with a clue.lock to make that fast). Its resolver lives in datpkgr, a language-agnostic kit: a lazy depth-first search with backtracking, no SAT solver, where the nearest constraint wins. It caches the versions it discovers with git ls-remote, and adds venvs (via choosenim), docs, deploys and Nimony builds.

conda / pixi

Continuum (2012) … prefix.dev (2023)
the index already knows

Installs prebuilt packages into an environment folder. Every package's version, dependencies and hash are in the channel's index (repodata.json), so it solves first and downloads once. The rest of this page.

They differ in where packages go (a hidden store, a deps/ folder, a sibling workspace) and in how versions are chosen (a solver, a solver, no solver, a depth-first search). They share the same first step: to learn the dependencies of nimib you must fetch nimib, at a version you chose from its git tags, and read a file in it. Then do the same for each dependency. treeform's README puts the cost plainly: nimble took almost two minutes to install Fidget2's dependencies in CI, cloning everything in parallel took three seconds. Parallelism helps within one level of the tree, but not across levels: you can't clone the grandchildren before you have read the children.

👑 Nim

packages.json is a phone book, not an index: it tells you where to call, not what you will hear. Everything else (versions, dependencies, checksums) is discovered by cloning. That is the one design decision every Nim package manager has inherited.

Conda, for someone who last looked in 2016 ↑ Contents

Wolf's slide at Compute Paris had this question on it: "But I thought Conda is for Python?!", and the answer underlined in yellow: conda is a general-purpose, cross-platform, language-agnostic package manager. Here is his wheel, redrawn, with a spoke left for us:

The trick is that a conda package knows nothing about languages. It is a compressed folder of files (bin/nimby, lib/libz.so, share/nimble/pkgs2/jsony-1.1.6/jsony.nim, …) plus an info/ folder of metadata. Installing it means unpacking those files into an environment, which is just a directory, a prefix (hence the company name). A Python package puts files in lib/python3.13/site-packages, an R package in lib/R/library, a C library in lib/ and include/. A Nim package can put its sources wherever the Nim compiler looks. That's it.

What changed since you last looked ↑ Contents

The conda you may remember was slow (a Python SAT solver on a huge index) and tied to Anaconda's defaults channel, with its license terms. Most of the work since then happened around Wolf Vollprecht: first at QuantStack, where he started mamba (the solver rewritten in C++ on top of openSUSE's libsolv), then at prefix.dev, which rewrote the whole stack in Rust as a set of libraries called rattler.

The critical concept: who knows the graph, and when? ↑ Contents

Here is the difference between the two worlds, slowed down. Pick a package and press Next round trip. Both sides make one network round trip per press (in parallel, when there are several things to fetch). The graphs are real: they are the requires of each package at its latest tag, as nimforge read them for the PoC below. Try fidget2, treeform's UI library and the project behind nimby's two-minute CI: 22 packages, five levels deep.

install

Clone-first pays one tag listing and one clone per level of the tree, and it runs code (or parses code) from each package to find out the next level. Index-first pays one index fetch and one download however deep the tree is, and the solve, which is the clever part, happens on your machine with nothing but metadata. That metadata was computed once, when the package was built: someone cloned and read the .nimble file, so that nobody else has to.

How this interactive is built, with its source

It takes three small pieces, and no framework.

  1. The data comes from the PoC's own recipes. At build time, raceData (in index.nim) walks poc/recipes/nim-* and poc/graphs/nim-*. Those are the recipes nimforge wrote from packages.json and from each package's .nimble file. From each recipe.yaml, it keeps the version and the nim-* names listed under run:. Then, starting from each root (nimib, pixie, fidget2), it collects the graph that can be reached and stores it as JSON: {pkg: {deps: {name: [deps]}, versions: {name: version}}}.

  2. A custom nimib block puts it on the page. nbRace (in lib/blocks.nim) writes the empty lanes and the buttons as HTML. It puts the JSON in a <script type="application/json"> tag, and inlines lib/race.js, which is read with staticRead when the page compiles. Nothing is loaded from a CDN, so it works inside a claude.ai artifact too.

  3. The script works out both stories in advance, as frames.

    • levels splits the graph by depth, breadth first.
    • clonePlan makes one frame per round trip. The first is GET packages.json. Then, for each level of the tree, there is one frame for git ls-remote --tags on the frontier, and one frame for a clone that reads the .nimble files to find the next level.
    • indexPlan makes three frames: GET repodata (every edge is known), a local solve, and one download of everything.

    Each frame holds the state of every package (unknown, known, busy or got) and the counters. Next round trip moves both lanes forward by one frame, and render redraws them from it. Play is a timer on the same step.

So the race is a model, not a measurement. One press is one network round trip, and fetches made in parallel count as one. The measured times are in the bars below.

proc raceData(roots: openArray[string]): JsonNode =
  ## The dependency graphs of the recipes nimforge wrote (poc/recipes), for the race.
  var deps = initTable[string, seq[string]]()
  var versions = initTable[string, string]()
  for dir in toSeq(walkDirs("poc/recipes/nim-*")) & toSeq(walkDirs("poc/graphs/nim-*")):
    let name = dir.lastPathPart["nim-".len .. ^1]
    if name == "activation": continue
    var inRun = false
    deps[name] = @[]
    for line in readFile(dir / "recipe.yaml").splitLines:
      if line.startsWith("  version: \""): versions[name] = line.split('"')[1]
      if line.strip == "run:": inRun = true; continue
      if inRun:
        if not line.startsWith("    - "): inRun = false; continue
        let d = line.strip[2..^1].split(' ')[0]
        if d.startsWith("nim-") and d != "nim-activation": deps[name].add d["nim-".len .. ^1]
  result = newJObject()
  for root in roots:
    var g = newJObject()
    var v = newJObject()
    var todo = @[root]
    while todo.len > 0:
      let n = todo.pop
      if g.hasKey(n): continue
      g[n] = %deps[n]
      v[n] = %versions[n]
      todo.add deps[n]
    result[root] = %*{"deps": g, "versions": v}

// The race: who knows the dependency graph, and when.
// Clone-first (nimble, atlas, nimby): the registry only maps names to git URLs, so the graph is
// discovered level by level, by listing tags and cloning each package to read its .nimble file.
// Index-first (conda, pixi): the channel's repodata already holds every edge, so one fetch gives
// the whole graph, the solve is local, and every package is downloaded at once.
(function () {
  const data = JSON.parse(document.getElementById("rc-data").textContent);
  const $ = (id) => document.getElementById(id);
  let pkg = Object.keys(data)[0], step = 0, timer = null, plans = null;

  function levels(deps, root) {
    const depth = { [root]: 0 }, q = [root];
    while (q.length) {
      const n = q.shift();
      for (const d of deps[n] || []) if (!(d in depth)) { depth[d] = depth[n] + 1; q.push(d); }
    }
    const out = [];
    for (const [n, l] of Object.entries(depth)) (out[l] = out[l] || []).push(n);
    return out;
  }

  // Each plan is a list of frames: {log, st: {name: state}, m: {meter: value}}.
  function clonePlan(deps, root) {
    const names = Object.keys(deps), st = {}, m = { "round trips": 0, "git ops": 0, ".nimble read": 0 };
    names.forEach((n) => (st[n] = "unknown"));
    const frames = [{ log: "nothing known yet", st: { ...st }, m: { ...m } }];
    const snap = (log) => frames.push({ log, st: { ...st }, m: { ...m } });
    m["round trips"]++; st[root] = "known";
    snap("GET packages.json (2.9 MB): " + root + " → its git URL. No versions, no dependencies.");
    let frontier = [root];
    const seen = new Set([root]);
    while (frontier.length) {
      m["round trips"]++; m["git ops"] += frontier.length;
      frontier.forEach((n) => (st[n] = "busy"));
      snap("git ls-remote --tags, " + frontier.length + " repo" + (frontier.length > 1 ? "s" : "") + " in parallel: which versions exist?");
      m["round trips"]++; m["git ops"] += frontier.length; m[".nimble read"] += frontier.length;
      const next = [];
      for (const n of frontier) {
        st[n] = "got";
        for (const d of deps[n]) if (!seen.has(d)) { seen.add(d); next.push(d); st[d] = "known"; }
      }
      snap("git clone at the tag, read " + frontier.map((n) => n + ".nimble").join(", ") +
        (next.length ? " → found " + next.join(", ") : " → no new dependencies"));
      frontier = next;
    }
    frames[frames.length - 1].done = true;
    return frames;
  }

  function indexPlan(deps, root) {
    const names = Object.keys(deps), st = {}, m = { "round trips": 0, "downloads": 0, ".nimble read": 0 };
    names.forEach((n) => (st[n] = "unknown"));
    const frames = [{ log: "nothing known yet", st: { ...st }, m: { ...m } }];
    const snap = (log) => frames.push({ log, st: { ...st }, m: { ...m } });
    m["round trips"]++; names.forEach((n) => (st[n] = "known"));
    snap("GET repodata (noarch + linux-64): every package, version and dependency edge is in it.");
    names.forEach((n) => (st[n] = "busy"));
    snap("solve locally (resolvo, a SAT solver in Rust): no network. Picks " + names.length + " packages.");
    m["round trips"]++; m["downloads"] = names.length; names.forEach((n) => (st[n] = "got"));
    snap("download " + names.length + " .conda files at once, hard-link them into the env. Done.");
    frames[frames.length - 1].done = true;
    return frames;
  }

  function lane(el, title, sub, frames, versions, lv) {
    const f = frames[Math.min(step, frames.length - 1)];
    let g = "";
    lv.forEach((names, i) => {
      g += '<div class="rc-level"><span class="rc-level-n">' + (i === 0 ? "root" : "dep " + i) + "</span>";
      for (const n of names) {
        const s = f.st[n];
        const label = s === "unknown" ? "?" : s === "got" ? n + " " + versions[n] : n;
        g += '<span class="rc-node ' + s + '">' + label + "</span>";
      }
      g += "</div>";
    });
    const meters = Object.entries(f.m).map(([k, v]) => "<span><b>" + v + "</b> " + k + "</span>").join("");
    el.innerHTML = "<h4>" + title + '</h4><p class="rc-sub">' + sub + '</p><div class="rc-meters">' + meters +
      '</div><div class="rc-graph">' + g + '</div><p class="rc-log">' + (f.done && step >= frames.length - 1 ? "✓ " : "") + f.log + "</p>";
  }

  function render() {
    const d = data[pkg], lv = levels(d.deps, pkg);
    lane($("rc-clone"), "Clone-first: nimble, atlas, nimby", "the registry maps names to git URLs; the graph lives in the .nimble files",
      plans.clone, d.versions, lv);
    lane($("rc-index"), "Index-first: conda, pixi", "the channel's repodata already holds every edge", plans.index, d.versions, lv);
    const last = Math.max(plans.clone.length, plans.index.length) - 1;
    $("rc-step").disabled = step >= last;
    const c = plans.clone[plans.clone.length - 1].m, i = plans.index[plans.index.length - 1].m;
    $("rc-verdict").innerHTML = step >= last
      ? "<b>" + pkg + "</b>: clone-first needed <b>" + c["round trips"] + "</b> round trips, one after the other, and <b>" +
        c["git ops"] + "</b> git operations. Index-first needed <b>" + i["round trips"] +
        "</b>, whatever the depth of the tree. The difference grows with every level of dependencies."
      : step >= plans.index.length - 1
        ? "conda is done. Clone-first still cannot see the bottom of the tree."
        : "Press <b>Next round trip</b>: both sides make one network round trip per press.";
  }

  function reset() {
    stop(); step = 0;
    plans = { clone: clonePlan(data[pkg].deps, pkg), index: indexPlan(data[pkg].deps, pkg) };
    render();
  }
  function stop() { if (timer) { clearInterval(timer); timer = null; $("rc-play").textContent = "▶ Play"; } }
  function next() {
    const last = Math.max(plans.clone.length, plans.index.length) - 1;
    if (step < last) { step++; render(); }
    if (step >= last) stop();
  }

  const chips = $("rc-pkgs");
  for (const name of Object.keys(data)) {
    const b = document.createElement("button");
    b.type = "button"; b.className = "rc-chip"; b.textContent = name;
    b.setAttribute("aria-pressed", String(name === pkg));
    b.onclick = () => {
      pkg = name;
      chips.querySelectorAll("button").forEach((x) => x.setAttribute("aria-pressed", String(x === b)));
      reset();
    };
    chips.appendChild(b);
  }
  $("rc-step").onclick = () => { stop(); next(); };
  $("rc-reset").onclick = reset;
  $("rc-play").onclick = () => {
    if (timer) return stop();
    const last = Math.max(plans.clone.length, plans.index.length) - 1;
    if (step >= last) reset();
    $("rc-play").textContent = "⏸ Pause";
    timer = setInterval(next, 1100);
  };
  reset();
})();

2. The bridge: one environment variable ↑ Contents

How does nim find a package that conda installed? It turns out Nim has had the answer for years. In compiler/commands.nim, the nimblepath switch (which the default nim.cfg uses for ~/.nimble/pkgs2) is replaced by $NIMBLE_DIR/pkgs2 whenever that variable is set:

And nimble reads NIMBLE_DIR too. So the convention writes itself: a Nim library package puts its sources in $PREFIX/share/nimble/pkgs2/<name>-<version>/ (the folder layout nimble uses, so the compiler picks the highest version), and an activation script sets NIMBLE_DIR=$CONDA_PREFIX/share/nimble. For the PoC that script is its own tiny package, nim-activation; in the real thing it belongs in the nim package itself (section 8).

3. nimforge: from the phone book to recipes ↑ Contents

To package Nim libraries we need recipes. nimforge.nim does for packages.json what rattler-build generate-recipe does for PyPI and CRAN: look the name up, list the git tags, pick the highest, clone it, read the .nimble file (version, srcDir, requires), translate nimble's version operators (^=, ~=, &) to conda's, and recurse into the dependencies. Package names get a nim- prefix, like R's r-. (Not just for tidiness: r-nimble, an R package for Bayesian models, is already on conda-forge.)

proc cmp(a, b: seq[int]): int =
  for i in 0 ..< max(a.len, b.len):
    let x = if i < a.len: a[i] else: 0
    let y = if i < b.len: b[i] else: 0
    if x != y: return cmp(x, y)

proc versionKey(v: string): seq[int] =
  for part in v.split('.'):

proc latestTag(url: string): string =
  ## Highest version-looking tag, "" if the repo has no tags.
  var tags: seq[string]
  for line in sh("git ls-remote --tags --refs " & url).splitLines:
    if line.len == 0: continue
    let t = line.split("refs/tags/")[1]
    if t.strip(chars = {'v'}).allIt(it in Digits or it == '.'): tags.add t
  if tags.len == 0: return ""
  tags.sort(proc (a, b: string): int =
    cmp(versionKey(a.strip(chars = {'v'})), versionKey(b.strip(chars = {'v'}))))
  tags[^1]

proc condaName*(nimName: string): string =
  "nim-" & nimName.toLowerAscii.replace("_", "-")

proc toCondaSpec*(nimSpec: string): string =
  ## nimble: ">= 1.2", "^= 0.8", "~= 1.2.3", "== 1.0", ">= 1 & < 2", "#head"
  var parts: seq[string]
  for c in nimSpec.split('&'):
    let c = c.strip
    if c.len == 0 or c.startsWith("#"): continue   # git refs: no conda equivalent
    if c.startsWith("^="):
      let v = c[2..^1].strip
      let p = v.split('.')
      let major = parseInt(p[0])
      parts.add if major > 0: &">={v},<{major+1}" else: &">={v},<0.{parseInt(p[1])+1}"
    elif c.startsWith("~="):
      let v = c[2..^1].strip
      let p = v.split('.')
      parts.add &">={v},<{p[0]}.{parseInt(p[1])+1}"
    else:
      parts.add c.replace(" ", "")
  parts.join(",")

proc parseNimble(path: string, p: var Pkg) =
  ## A tiny "declarative" reader: good enough for most .nimble files.
  for raw in readFile(path).splitLines:
    let line = raw.strip
    template value(): string = line.split('=', 1)[1].strip.strip(chars = {'"'})
    if line.startsWith("version") and '=' in line: p.version = value()
    elif line.startsWith("srcDir") and '=' in line: p.srcDir = value()
    elif line.startsWith("license") and '=' in line: p.license = value()
    elif line.startsWith("description") and '=' in line: p.description = value()
    elif line.startsWith("requires"):
      for item in line["requires".len..^1].split(','):
        let item = item.strip.strip(chars = {'"', ' ', '(', ')'})
        if item.len == 0: continue
        var i = 0
        while i < item.len and item[i] in IdentChars + {'-'}: inc i
        let (name, spec) = (item[0..<i], item[i..^1].strip)
        if name.cmpIgnoreStyle("nim") == 0: p.nimSpec = toCondaSpec(spec)
        else: p.requires.add Req(name: name, spec: toCondaSpec(spec))

Nim is already in conda: a survey ↑ Contents

Wolf was right: there is Nim in conda, in two places.

conda-forge: the compiler, and nothing else ↑ Contents

conda-forge/nim-feedstock has packaged the Nim compiler since 8 November 2019. Its history is a small relay race: Christopher Dunn (pb-cdunn, then at PacBio, who needed Nim for genome assembly tools) created it; Marcel Bargull (a conda-forge and bioconda core member) made it work on macOS in July 2020 and wired Nim to conda's compilers; Benjamin Cross (btcross26) kept 1.4.x current in 2021; Daylin Morgan (daylinmorgan, well known in the Nim community) brought it to 2.0 in 2023 and moved CI to Azure in 2024. Since then the bot does the updates: 2.0.2 to 2.2.6 were merged automatically.

Then it stopped. The bot's pull requests for 2.2.10 (April 2026), 2.2.12 (September) and 2.4.0 (October) are open and unmerged, so conda-forge still ships 2.2.6 while Nim is at 2.4.2. conda-forge's dependency graph (the bot's graph.json) shows no other feedstock depends on nim, not even to build. And the name nim is in conda-forge's arm osx addition migration, which never landed: hence no osx-arm64.
