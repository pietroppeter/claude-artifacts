Nometabelline

11 November 2026

tabelline in eight languages

Nim compiles to C, so tabelline can be a C library, and every language that calls C can draw a tabelline table. Proofs of concept for C, Zig, Rust, Julia, Java, Erlang, Gleam and Elixir, and a check that all of them print the same HTML as Nim, byte for byte.

Great tables in every language found that outside R and Python almost no language has gt's grammar: Rust, Zig, Gleam, Ruby and the JVM have table printers, not display tables. This post is the other half: tabelline, called from eight of those languages. Not ports yet; proofs that a port can start from a working table.

From the simplest to the most complex: one table to draw, a Nim library seen from C, the two layers of the C API, how every verb gets there without being written twice, the eight languages, the check, and what a real repository would add. The code is in experiments/polyglot/ of this repository, until it moves to a repository of its own.

A Nim library is a C library

Nim compiles to C, then a C compiler makes the program. With --app:lib it makes a shared library instead (.so on Linux, .dylib on macOS, .dll on Windows), and a proc marked exportc keeps its name in it, so C can find it:

proc tbl_version(): cstring {.exportc, dynlib, cdecl.} = "0.0.1"

exportc keeps the name tbl_version, dynlib puts it in the library's table of exported names, cdecl uses C's calling convention. Then a C header declares it, and any C program can call it:

const char *tbl_version(void);

Four things make a real library out of that.

  1. Nim starts itself. A Nim library runs its module-level code (tabelline's palettes and locales) when it is loaded, before the first call: no NimMain() to call by hand.
  2. Who frees what. A string the library returns is copied into memory from C's malloc, and the caller gives it back with tbl_free. Strings the caller passes are only read.
  3. Errors without exceptions. C has no exceptions, so a call that fails returns NULL (or -1), and tbl_error() says why. The message is per thread.
  4. Foreign threads. The JVM and the BEAM call from threads Nim did not start. With -d:useMalloc Nim allocates with C's allocator, which any thread may use.

Layer 1: one call

The simplest C API a table library can have is one function: the table in, the table out. The table is JSON, as in lt's spec: the data, the stub, and the verbs in order, each an object with one key, its name, and its arguments as the value: an array for positional ones, an object for named ones.

The arguments are written as JSON writes them, and read back as tabelline's types: a column selection is a name, a list of names, or a rule ({"numeric": true}, {"startsWith": "x"}); rows are indices or {"where": ["moons", ">", 50]}; a text is a string, {"md": ...} or {"html": ...}; a location is "title" or {"body": {"columns": ..., "rows": ...}}; a style is {"fill": ...} or {"text": {"weight": "bold"}}; a palette is a name or a list of colours.

From C that is all it takes:

char *html = tbl_render_spec(spec_json, "html");   /* or "page", "text", "markdown" */
if (!html) fprintf(stderr, "%s\n", tbl_error());
tbl_free(html);
c/spec.c: any spec file, rendered 22 lines
/* Layer 1: a whole table as JSON (a file, or stdin), rendered in one call. */
#include <stdio.h>
#include <stdlib.h>
#include "tabelline.h"

int main(int argc, char **argv) {
  FILE *f = argc > 1 ? fopen(argv[1], "rb") : stdin;
  if (!f) { perror(argv[1]); return 1; }
  size_t cap = 1 << 16, len = 0, got;
  char *spec = malloc(cap);
  while ((got = fread(spec + len, 1, cap - len - 1, f)) > 0) {
    len += got;
    if (len + 1 == cap) spec = realloc(spec, cap *= 2);
  }
  spec[len] = '\0';
  char *out = tbl_render_spec(spec, argc > 2 ? argv[2] : "html");
  if (!out) { fprintf(stderr, "tabelline: %s\n", tbl_error()); return 1; }
  fputs(out, stdout);
  tbl_free(out);
  free(spec);
  return 0;
}

Layer 2: a table you build

JSON is fine for verbs, not for data: a million numbers should not be written as text and read back. So the second layer keeps a table on the library's side, behind a handle (tbl_table *), and the caller fills it with typed arrays: tbl_add_doubles, tbl_add_ints, tbl_add_bools, tbl_add_strings (with NaN and NULL for missing values), or tbl_add_json for lists and records. Settings (rownameCol, groupnameCol, id, locale) come next, then the verbs, one call each, with their arguments in JSON, and last the rendering.

On the Nim side, a handle is a ref object kept alive with GC_ref and released with GC_unref in tbl_drop. The table is made at the first verb, when the columns and the settings are known.

Every verb, without writing it twice

The library takes 92 of tabelline's verbs, 99 forms of them counting overloads, each with its own parameters and defaults. Writing a C function or a JSON reader for each would be a second tabelline to keep in step with the first. So there is none: a macro reads the signatures.

verbsFromSignatures(tabHeader, tabSpanner, fmtNumber, ...) gets, for each overload, its parameters, their types (getTypeImpl) and their defaults (getImpl), and writes a branch of applyVerb(t, name, args): when args fits the form (no unknown names, the required ones given), convert each argument with conv(json, T) (or take the default), and call the verb. A form whose types have no conv is left out at compile time (when compiles). 93 of the 99 forms are in; the six left out take a Nim proc (fmt, a style function), nanoplot options or a theme object.

capi/verbs_json.nim: the macro 96 lines
macro verbsFromSignatures*(verbs: varargs[typed]): untyped =
  ## For every overload of every verb: a branch of `applyVerb` that converts the JSON arguments
  ## to its parameter types and calls it, kept only `when compiles` (all its types convert).
  let t = ident"t"
  let a = ident"a"
  let name = ident"name"
  let why = ident"why"
  var body = newStmtList()
  var known = nnkBracket.newTree()
  var forms = newStmtList()
  let fs = ident"fs"
  for v in verbs:
    let syms = if v.kind in {nnkClosedSymChoice, nnkOpenSymChoice}: toSeq(v.children) else: @[v]
    let vname = $syms[0]
    known.add newLit(vname)
    var branch = newStmtList()
    for s in syms:
      let impl = s.getImpl
      when defined(debugVerbs):
        if vname == "tabHeader": echo impl.kind, " generic=", impl[2].kind, " ", s.getTypeImpl.repr
      if impl.kind notin {nnkProcDef, nnkFuncDef} or impl[2].kind != nnkEmpty: continue  # generic
      let ty = s.getTypeImpl  # types filled in, also for `rows = allRows()`
      let fp = ty[0]
      let ip = impl[3]
      if fp.len < 2 or "Tabella" notin fp[1][^2].repr: continue
      var names, required: seq[string]
      var decls = newStmtList()
      var call = newCall(ident(vname), t)
      var probe = newCall(ident(vname), t)
      var idx = 0
      var dflts: seq[NimNode]
      for k in 1 ..< ip.len:  # defaults from the source
        for m in 0 ..< ip[k].len - 2: dflts.add ip[k][^1]
      for k in 2 ..< fp.len:
        let pname = $fp[k][0]
        let ptype = seqType(fp[k][1])
        let dflt = dflts[k - 1]
        names.add pname
        let pv = ident("p_" & pname)
        let conv = if ptype.repr == "seq[string]" and pname == "palette":
                     newCall(ident"convPalette", newCall(ident"get", a, newLit(idx), newLit(pname)))
                   else: newCall(ident"conv", newCall(ident"get", a, newLit(idx), newLit(pname)), ptype)
        if dflt.kind == nnkEmpty:
          required.add pname
          decls.add quote do:
            let `pv`: `ptype` = `conv`
        else:
          let d = defaultExpr(dflt)
          decls.add quote do:
            let `pv`: `ptype` = (if has(`a`, `idx`, `pname`): `conv` else: `d`)
        call.add newNimNode(nnkExprEqExpr).add(ident(pname), pv)
        probe.add newNimNode(nnkExprEqExpr).add(ident(pname), conv.copyNimTree)
        inc idx
      let namesLit = newLit(names)
      let reqLit = newLit(required)
      let vnameLit = newLit(vname)
      let probe2 = probe.copyNimTree
      forms.add quote do:
        block:
          let `a` = Args()
          var `t`: Tabella
          when compiles(`probe2`): `fs`.add (`vnameLit`, `namesLit`, `reqLit`, true)
          else: `fs`.add (`vnameLit`, `namesLit`, `reqLit`, false)
      branch.add quote do:
        when compiles(`probe`):
          if fits(`a`, `namesLit`, `reqLit`):
            var ok = false
            try:
              `decls`
              ok = true
              return `call`
            except ArgError as e:
              if ok: raise
              `why`.add "\n  (" & `namesLit`.join(", ") & "): " & e.msg
    let vn = newLit(norm(vname))
    when defined(debugVerbs):
      if vname == "tabHeader": echo branch.repr
    body.add quote do:
      if norm(`name`) == `vn`:
        `branch`
        raise newException(ArgError, "no form of " & `name` & " takes " & $`a`.pos & " " &
          $`a`.named.keys.toSeq & `why`)
  let vnames = postfix(ident"verbNames", "*")
  let apply = postfix(ident"applyVerb", "*")
  let vforms = postfix(ident"verbForms", "*")
  result = quote do:
    proc `vforms`(): seq[(string, seq[string], seq[string], bool)] =
      ## Every overload of every verb: its name, parameters, required ones, and whether it takes JSON.
      var `fs`: seq[(string, seq[string], seq[string], bool)]
      `forms`
      `fs`
    const `vnames` = `known`
    proc `apply`(`t`: sink Tabella, `name`: string, `a`: Args): Tabella =
      var `why` = ""
      `body`
      raise newException(ArgError, "unknown verb " & `name`)

Names are compared the way Nim compares identifiers: case and underscores do not count. So fmt_number, fmtNumber and FmtNumber are the same verb, and use_seps is useSeps, and each language writes them in its own style: Rust and Elixir write fmt_number, Java fmtNumber. And tbl_verbs() returns the list of forms as JSON, so a binding can check its names, or be generated.

Eight languages

Each binding is small, in the language's own style, with no dependencies (the sandbox could not download packages for most of them, and a proof of concept is clearer without). From the closest to C to the furthest.

1C

The header and -ltabelline. Layer 1 and layer 2, as above.

2Zig

extern fn declarations, written by hand: Zig 0.17 has no @cImport. A verb's arguments are any Zig value, written as JSON by std.json.

3Rust

A crate with no dependencies: extern "C", build.rs to link, a builder that keeps the first error, and list! and args! macros.

4Julia

ccall. One Julia function per verb, made when the module loads, from tbl_verbs(): fmt_number, for |>.

5Java

The foreign function and memory API, final in Java 22: no JNI, no C to compile. Lists and maps become JSON.

6Erlang

One NIF, render_spec, on a dirty scheduler. The table is a map, written as JSON by OTP 27's json.

7Gleam

A table is a Gleam value, built with |>, typed helpers and custom types for locations and styles. The same NIF renders it.

8Elixir

Keyword lists and pipes, the same NIF. Keyword lists keep their order, so labels do too.

C, Zig and Rust: the systems languages

Zig is the closest to C, and it shows: the binding is the C declarations in Zig and four methods. Its nicest part is the arguments: t.verb("fmtNumber", .{ .columns = "mass", .decimals = 2 }) passes an anonymous struct, and std.json writes it as an object; a tuple .{ "Size", .{ "diameter", "mass" } } becomes an array. No JSON library to learn, no strings to escape.

Julia and Java: two runtimes that call C on their own

Julia calls C with ccall, no glue at all. The binding goes one step further: when the module loads it asks the library for its verbs (tbl_verbs()) and defines a Julia function for each, in Julia's naming (fmtNumber becomes fmt_number). Called with a table it applies the verb; called without one it returns a function, so tables read as pipelines.

Java 22 made the foreign function and memory API final: a MethodHandle per C function, an Arena for the memory of one call, no JNI and no C to compile. The binding is one class; Kotlin, Scala and Clojure can use it as it is. One surprise: System.out writes in the platform's encoding, which in a bare container is ASCII, so the example writes bytes.

Erlang, Gleam and Elixir: one NIF for the BEAM

The BEAM calls C through NIFs: a C file compiled against erl_nif.h, loaded by a module. One NIF is enough, the first layer: render_spec(Spec, Format), on a dirty CPU scheduler so that a big table does not block the schedulers that run everything else. On the BEAM a table is naturally a value (a map, a record), so it is built in the language and only rendered by C.

beam/c_src/tabelline_nif.c 12 lines
static ERL_NIF_TERM render_spec(ErlNifEnv *env, int argc, const ERL_NIF_TERM argv[]) {
  ErlNifBinary spec, format;
  if (argc != 2 || !cstr(env, argv[0], &spec)) return enif_make_badarg(env);
  if (!cstr(env, argv[1], &format)) { enif_release_binary(&spec); return enif_make_badarg(env); }
  char *out = tbl_render_spec((const char *)spec.data, (const char *)format.data);
  enif_release_binary(&spec);
  enif_release_binary(&format);
  if (!out) return enif_make_tuple2(env, enif_make_atom(env, "error"), binary(env, tbl_error()));
  ERL_NIF_TERM r = enif_make_tuple2(env, enif_make_atom(env, "ok"), binary(env, out));
  tbl_free(out);
  return r;
}

## A Nim library is a C library

Nim compiles to C, then a C compiler makes the program. With `--app:lib` it makes a shared
library instead (`.so` on Linux, `.dylib` on macOS, `.dll` on Windows), and a proc marked
`exportc` keeps its name in it, so C can find it:

```nim
proc tbl_version(): cstring {.exportc, dynlib, cdecl.} = "0.0.1"
```

`exportc` keeps the name `tbl_version`, `dynlib` puts it in the library's table of exported
names, `cdecl` uses C's calling convention. Then a C header declares it, and any C program can
call it:

```c
const char *tbl_version(void);
```

Four things make a real library out of that.

1. **Nim starts itself.** A Nim library runs its module-level code (tabelline's palettes and
   locales) when it is loaded, before the first call: no `NimMain()` to call by hand.
2. **Who frees what.** A string the library returns is copied into memory from C's `malloc`, and
   the caller gives it back with `tbl_free`. Strings the caller passes are only read.
3. **Errors without exceptions.** C has no exceptions, so a call that fails returns `NULL` (or
   `-1`), and `tbl_error()` says why. The message is per thread.
4. **Foreign threads.** The JVM and the BEAM call from threads Nim did not start. With
   `-d:useMalloc` Nim allocates with C's allocator, which any thread may use.

## Layer 1: one call

The simplest C API a table library can have is one function: the table in, the table out. The
table is JSON, as in lt's spec: the data, the stub, and the verbs in order, each an object with
one key, its name, and its arguments as the value: an array for positional ones, an object for
named ones.
"""

## Every verb, without writing it twice

The library takes 92 of tabelline's verbs, 99 forms of them counting overloads, each with its
own parameters and defaults. Writing a C function or a JSON reader for each would be a second tabelline to keep in
step with the first. So there is none: a macro reads the signatures.

`verbsFromSignatures(tabHeader, tabSpanner, fmtNumber, ...)` gets, for each overload, its
parameters, their types (`getTypeImpl`) and their defaults (`getImpl`), and writes a branch of
`applyVerb(t, name, args)`: when `args` fits the form (no unknown names, the required ones
given), convert each argument with `conv(json, T)` (or take the default), and call the verb.
A form whose types have no `conv` is left out at compile time (`when compiles`). 93 of the 99
forms are in; the six left out take a Nim proc (`fmt`, a style function), nanoplot options or a
theme object.
